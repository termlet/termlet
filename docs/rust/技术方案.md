# Termlet Rust 版技术方案

> 作者：ruan
> 日期：2026-10-15
> 功能规格：旧版（Electron + React 的桌面端、Go 的 Core，没有公开）的 Termlet 1.0.0-beta.1，现在的功能以[用户指南](../guide.md)为准。本文写 Rust 版的设计，以及这样选的理由；表中的"旧版技术方案"等出处是维护者的内部文档，不在公开仓库中。

## 1. 目标

用 Rust + GPUI（gpui-kit）重写 Termlet：界面、核心、命令行工具全部换成 Rust，功能与旧版对齐，打字回显、大量输出、启动速度与内存占用明显好于 Electron 版。

用户已确认的前提（2026-10-15）：

- 全部 Rust，不保留 Go Core。
- 数据格式重新设计，不导入旧版本的数据（旧版本只在本机测试过，没有用户）。
- 技术栈参考 [ShellRS](https://github.com/since2006/shell-rs)，择优选用，不照搬。

## 2. 从旧版与前辈产品得到的经验

| 经验 | 来源 | Rust 版的做法 |
|---|---|---|
| 进程分离带来大量额外复杂度：Core 生命周期与版本接管、本机 HTTP/WS 的 token、Host/Origin 校验、通道归属、渲染进程重载后补发输出、Electron 子进程退出缺陷 | 旧版技术方案 4.2、4.4、9.1 | **单进程**：界面与核心在同一进程，核心以库的形式链接进来；只有给 CLI 用的本机 IPC。上述问题整类消失 |
| fork 大量上游（GPUI、alacritty、vte、russh），维护负担重 | OxideTerm | 只用 crates.io 上的原版；上游缺的功能在外面补，必要时给上游提 PR |
| 单个 crate、12 万行，编译慢，核心逻辑离不开界面测试 | ShellRS | **分层 workspace**：核心不依赖 GPUI，可以单独编译、测试，以后给移动端用 |
| 秘密只进系统钥匙串：Windows 凭据管理器放不下 RSA 私钥，只好落成文件；备份、同步也难做 | ShellRS | 沿用旧版做法：钥匙串只存主密钥，秘密用 AES-256-GCM 加密后存进数据库 |
| 云同步是后加的，按条目合并要靠基准快照补；每加一个主机选项都要改表、改接口、改同步映射 | 旧版第 5.12 节、各批迁移 | **从一开始按同步设计**：每个条目有全局唯一 ID、修改时间、删除墓碑；条目内容是带版本号的结构体，存成 JSON 文档，加选项不用改表 |
| 开发构建与正式数据混在一个数据目录 | 旧版开发过程 | 调试构建默认用 `termlet-dev` 数据目录 |
| 终端细节被集中提意见：Ctrl+W 被抢、没有矩形选择、编码不能切换、没有 ZModem、浅色界面不能配深色终端 | ShellRS 发布帖 | 旧版已经做了的全部保留，按旧版的行为逐项对齐 |
| 关键字高亮用 Alacritty 的网格搜索时，DFA 不支持 `\b`，`^` 在第一行之后失效 | ShellRS | 关键字高亮与终端搜索用 `regex` 匹配可见区的文本，不用 alacritty 自带的 `RegexSearch` |

## 5. 进程模型

```
Termlet.exe（单进程，每个数据目录一个实例）
  ├─ GPUI 窗口（可以没有窗口：被 CLI 拉起时是 headless 模式；关闭全部窗口后退出）
  ├─ 核心服务（termlet-core，tokio 运行时）
  └─ CLI 服务：Windows 命名管道 / Unix 套接字，只允许当前用户

termlet（命令行，薄客户端）
  └─ 连接 CLI 服务；没有实例在运行时以 --headless 拉起 Termlet.exe（设置中可关闭，关闭后提示先打开 Termlet）
```

- **单实例**：启动时对 `{数据目录}/run/instance.lock` 加排他锁。拿不到锁说明已有实例：连上它的 CLI 服务，发送 `activate`（带上启动参数，例如堡垒机传来的 `ssh://` 链接）后退出，由已有实例打开窗口或新 Tab。
- **headless 模式**：被 CLI 拉起时不开窗口；没有 CLI 请求 10 分钟后退出。用户此时启动 Termlet，已有实例直接打开主窗口。设置“命令行工具”中的“Termlet 没有打开时也能使用（自动在后台启动）”默认开启，关掉后 `termlet` 不拉起，返回 `app_not_running`（退出码 7）；应用把这一项写进 `{数据目录}/cli-launch.json`，没有运行的应用也能让命令行读到。
- **关闭窗口**：关闭全部终端、SFTP 与端口转发（与旧版"转发随窗口关闭而停止"一致）；关闭全部窗口后退出（不再在后台继续服务：没有托盘图标，用户看不出它还在运行；需要时命令行会再拉起），还有命令行请求在执行时等它们做完。
- **版本不一致**（更新后旧实例还在运行）：新进程请旧实例退出，等它释放锁后再启动。
- **CLI 服务的访问控制**：命名管道名含数据目录的哈希，设受保护的 DACL（只有当前用户与 SYSTEM）；Unix 套接字在 0700 的 `run/` 目录中。由操作系统做用户隔离，不需要 token。

## 6. 并发与数据流

- 核心持有一个 tokio 多线程运行时（全局一份），网络与文件 I/O 都在上面跑。GPUI 一侧用 `cx.spawn` 等待 tokio 任务的 `JoinHandle`，或从 `async-channel` 接收事件，再 `update` 实体。阻塞调用（钥匙串、SQLite 写入）放在 `spawn_blocking` 或 GPUI 的后台执行器。
- **终端数据**：每个终端一个引擎线程，独占终端内核；从传输（SSH 通道、PTY、Telnet、串口）读到的字节在这个线程上解析，之后由它填好可见区的快照、通知界面重绘（合并到下一帧），界面绘制时换走快照，不碰内核（见第 8 节的“线程”）。通道是有界的，解析跟不上时自然对 SSH 窗口与 PTY 形成背压，不再需要旧版的水位线 ACK 与 256KB 补发缓存。
- **传输的生命周期**：终端不用了（Tab 关闭、重连换上新的传输）时由引擎调用 `TerminalInput::close`——本地 shell 结束进程，SSH 关闭通道。不能只靠丢弃：引擎线程一直持有输入句柄（写终端的应答）。重连时引擎给每个传输编号，旧传输晚到的输出与结束不再生效。
- **SSH 连接**：共用连接的终端（复制会话、分屏）属于同一个连接组，连接池里只放弱引用，组里的终端都关闭后连接随之断开；断线后组里的终端各自重连时只建一条新连接、只认证一次。每条目标连接按保活间隔发 ping：10 秒没有回应报告"没有响应"，约保活间隔 × 3 仍没有回应才断开。会话结束原因分三种：服务器报告了退出码或信号的是正常结束；没有报告就关闭的是断线（自动重连）；其余是出错。
- **存储**：启动时把条目全部读进内存，读取都在内存中进行；修改时"先写库（事务）→ 成功后改内存 → 发变更事件"。写库失败时操作返回错误、内存不变，界面弹出错误，不会显示一个重启后就消失的修改。桌面端把存储包装成 GPUI 实体（`StoreModel`），CLI 服务改了主机时界面同样收到通知。

## 7. 数据设计

### 7.1 数据目录

| 平台 | 默认位置 |
|---|---|
| Windows | `%APPDATA%\termlet` |
| macOS | `~/Library/Application Support/termlet` |
| Linux | `~/.config/termlet` |

调试构建默认在同级的 `termlet-dev`；环境变量 `TERMLET_DATA_DIR` 可以指定任意位置。目录权限的收紧沿用旧版 4.2 的规则（公共位置或目录中有别的文件时只收紧 Termlet 自己的文件，失败只记警告）。

```
{数据目录}/
  data.db            主机、凭据、设置等全部数据（SQLite，另有 WAL 的附属文件）
  ui-state.json      只与这台电脑有关的界面状态：窗口位置、侧边栏宽度、分组折叠
  cli-launch.json    Termlet 没有运行时命令行是否自动拉起它（应用写、命令行读）
  cli-path.txt       加入 PATH 的命令行工具目录（换了安装位置时清理旧的条目）
  remote-config.json 已采用过的远程配置中最新的签发时间（防止重放旧的远程配置）
  usage.json         使用统计只记的两个 UTC 日期：第一次与上次发送成功（不在数据库中、不同步、不进备份；关闭统计时删除）
  run/               instance.lock、CLI 套接字（Unix 的 cli.sock；Windows 用命名管道）、权限已收紧的标记
  logs/              termlet.<日期>.log（按天滚动，保留 14 天）、崩溃记录 crash-*.json、dumps/（原生崩溃的内存转储）
  backups/           本机快照、迁移前的备份
  session-logs/      会话日志（目录可改）
  recordings/        会话录制（asciicast .cast，目录可改）
  updates/           自动更新下载的安装包（安装后下次启动时清理）
```

### 7.2 条目

可同步的数据都是"条目"：主机、分组、凭据档案、密钥、快捷命令与分组、端口转发规则、工作区、终端配色、设置。每类一张表，列相同：

| 列 | 说明 |
|---|---|
| `id TEXT PRIMARY KEY` | 全局唯一 ID（随机 128 位，base32 编码），CLI、导出、同步都用它，改名、改地址都不变 |
| `parent_id TEXT` | 所属分组等关系，只有需要按关系查的类有这一列 |
| `sort_key TEXT` | 分数索引（fractional index），拖动排序只改一行，同步时两边各自排序也能合并 |
| `doc TEXT` | 条目内容：带 `v` 版本号的结构体序列化成 JSON；加选项只加带默认值的字段，不改表 |
| `created_at`、`updated_at INTEGER` | 毫秒时间戳；同步按条目比较 `updated_at` |
| `deleted_at INTEGER` | 删除墓碑；同步完成、所有设备都看到后清理 |

不同步的数据单独建表：命令历史（加密）、审计日志、主机指纹、同步状态、本机设置。

- 所有表 `STRICT`；`PRAGMA user_version` 记录结构版本，迁移只往前升，升级前用 `VACUUM INTO` 备份；旧版本遇到新库直接报错、不动文件。
- 数据库里**不出现明文秘密**：有一个测试检查所有 `doc` 中不含秘密字段。

### 7.3 秘密与保险库

- **主密钥**：32 字节随机数，放在系统钥匙串（服务名 `termlet`，账户名含数据目录 ID，两个数据目录互不覆盖）。钥匙串不可用（Linux 没有 Secret Service）时改用主密码，Argon2id 派生。
- **秘密**（密码、私钥、私钥密码、TOTP 密钥、代理密码、WebDAV 密码）存在 `secrets` 表：AES-256-GCM，每条随机 nonce，附加数据为 `termlet:secret:v1:{id}`，防止两条秘密互换位置。私钥也加密存在库里，不落成文件。
- **校验值**：`meta` 表存一份用主密钥加密的固定内容。启动时解不开，说明主密钥不对（数据目录被拷到了另一台电脑或另一个账户），直接提示"重置保险库"（保留主机等数据，清空解不开的秘密），而不是等到连接时才失败。
- 内存中的秘密用 `zeroize` 包装，界面只在需要时取，`Debug` 输出中不出现。

### 7.4 设置

设置是一个带默认值的结构体，按分组（外观、终端、连接、安全……）存成 `settings` 表中的条目，每组一行，同步按组合并；只与本机有关的（本地终端、应用锁、CLI 开关、自动快照、日志与崩溃报告、使用统计的开关）存在不同步的 `local_settings`。

## 8. 终端

- **引擎与内核**：`TerminalEngine`（`engine.rs`）管引擎线程、传输与 shell 集成，解析与终端状态交给内核，只经内核接口 `Kernel`（`engine/kernel.rs`）使用它。内核现在是 `alacritty_terminal::Term`（`engine/alacritty.rs`，alacritty 的类型只出现在这个模块及其子模块 `marks.rs` 中），以后可以换成 libghostty-vt，换时只换这个后端。
  - **引擎自己的类型**（`grid.rs`、`colors.rs`）：网格坐标 `GridPoint`（行号 0 是屏幕第一行，负数是回滚）、单元格 `Cell`（字符、前景背景色 `Color`、属性 `CellFlags`：粗体斜体、各种下划线、删除线、暗淡、反色、隐藏、宽字符与占位、组合字符、超链接）、光标 `Cursor`、选区 `SelectionRange`、终端模式 `TerminalModes`（备用屏幕、应用光标键、括号粘贴、鼠标上报的种类与编码、kitty 键盘标志等）、网格大小 `GridDimensions`、跟着滚动的格子标记 `GridMark`、程序改过的颜色 `ColorOverrides`。视图、查找、关键词高亮、shell 集成、文本提取、按键与鼠标编码、配色只认这些类型。
  - **绘制读快照**：引擎线程把可见区（关键词高亮开着时加上跨出可见区的逻辑行，上下各最多一屏）拷进 `GridSnapshot`（组合字符另放，格子按值复制），视图绘制时用 `TerminalEngine::snapshot` 取走，之后排版、高亮只读快照。要读整个回滚的操作（查找、选中的文字、读命令、网址所在的逻辑行）经引擎的方法发给引擎线程，在内核上按 `GridText` 逐行取文字。
  - **哪些属于内核**：VT 解析，网格、回滚、光标、模式，程序改过的颜色，标题与响铃，终端的应答（设备属性、光标位置、窗口大小、颜色查询，按产生的顺序排队写出），同步更新（DEC 2026）的缓冲与 150 毫秒超时，选区与选中的文字，超链接，格子标记，kitty 键盘协议的标志栈，深浅色切换通知（DEC 2031）的开关与查询，不允许程序读写剪贴板（OSC 52）。其中 alacritty 没有或做得不对的由后端自己补：格子标记的滚动计数（alacritty 不报告滚了多少行）、kitty 键盘标志栈（`kitty_keyboard.rs`）、2031（`theme_mode.rs`），换 libghostty 后由它提供。
  - **内核之外**（换内核时不变）：shell 集成（OSC 133 / 633 / 7 / 9 / 777 / 1337）的扫描与命令历史、查找、关键词高亮、网址识别、逻辑行与文本提取、按键与鼠标的编码、配色的解析与对比度、绘制、输出旁路。扫描器顺带找出 kitty 键盘、2031 的请求与 RIS，在序列之后转给内核（`Kernel::keyboard_request` / `theme_request`），省得后端再扫一遍；自己解析这些序列的内核忽略这两个调用即可。
  - **线程**（`engine/worker.rs`）：每个终端一个引擎线程，从引擎创建到丢弃一直在（重连换传输时不换线程）。内核在这个线程上创建、只在这里使用、随引擎丢弃在这里释放，界面线程不碰它，所以内核不需要 `Send`、`Sync`（libghostty 的类型都是 `!Send`；测试构建中 alacritty 后端特意做成 `!Send`，有哪里退回跨线程使用内核时测试编译不过）。线程之间只传引擎自己的类型。
    - 引擎线程等三样：界面的命令（优先）、传输或回放的输出、超时（同步更新的 150 毫秒、按回车推断命令的 2 秒）。读到一段输出就解析，并把已到达的一起解析（一批最多 1MB）；两段之间有命令就先处理命令（先发布已解析的部分、交给输出观察者），界面等结果最多等一段。
    - 发布：每处理完一批输出或一组命令，把界面常读的小状态（模式、网格大小与可见区位置、光标、光标闪烁、2031、回滚行数、选区是否为空、是否开启了 shell 集成）与已处理的命令数写进共享区，并通知等待者。界面读状态前先等引擎线程处理完自己之前发出的命令（读到自己的修改，例如滚动后读可见区的位置），通常不用等；shell 事件、光标变化的事件在发布之后才发，界面收到时读到的已是新的。
    - 快照：内容有版本号（输出、滚动、选区、大小、快照参数等变了就加一）。有新输出要重绘、界面已取走上一份时，引擎线程发出重绘通知后接着填一份放进共享区（界面醒来的同时在填，没填完就等这一份）；界面绘制时手里的已是最新版本就什么也不做，共享区里有就交换缓冲（三份缓冲轮换，不复制、不分配），都不是才请引擎线程现在填（输出不断时）。命令补全提示要的“正在输入的命令”随快照一起填，与快照一致。
    - 命令：滚动、选区、清屏、改大小、插入提示、记下用户的输入（命令历史与补全提示）发出即返回；要结果的（查找、选中的文字、读命令、网址所在的逻辑行、超链接、屏幕快照、改回滚行数与光标默认样式）作为闭包发给引擎线程，界面有界等待（5 秒，引擎线程卡住时界面照常响应）。按键路径（回到底部、记下输入、写给传输）不等引擎线程：写给远端在界面线程上直接做，记下输入的命令在写之前发出，引擎线程先处理命令再解析输出，回显一定在它之后。
    - 取舍（2026-11-10，发布构建，200×50，i5-14400）：只按请求填（界面每帧发请求、等引擎线程填）每帧多一次线程往返（引擎线程睡着时中位数约 25 µs、p90 约 50 µs），而每帧绘制只有 0.2–0.8 ms，要慢 3%–25%；只在输出后填、界面拿现成的，滚动、拖动选区之后要晚一帧才看到。现在两者合用：有新输出时引擎线程先发重绘通知、接着填（界面醒来的同时在填），绘制时通常只换缓冲，内容没变时什么也不做（每帧比改前少取一次快照）；界面自己改了状态（滚动、选区、改大小）的那一帧等一次往返。量得：吞吐、每帧绘制、输出到拿到快照（约 38 µs）、零延迟回显到快照（约 33–36 µs）、回放跳到末尾都与改前持平，按键在界面线程上的处理 2.2→1.8 µs。
  - 内核的事件（标题、响铃、光标闪烁）经 `KernelEvents` 转成引擎事件（合并发送）。
- **键盘**：自己把按键编码成字节（xterm 规则，按光标键 / 小键盘的应用模式、修饰键），快捷键可自定义、不抢 Ctrl+W 等 shell 常用键（旧版规则：快捷键必须带 Ctrl+Shift 或 Alt）。
- **鼠标**：选区（普通、Alt 拖动的矩形、双击选词、三击选行），远端开启鼠标上报时按 SGR / 普通格式转发，按住 Shift 强制本地选择。
- **IME**：实现 GPUI 的 `EntityInputHandler`，预编辑文字画在光标处，候选框跟随光标（Windows 11 上用搜狗、微软拼音人工测试）。
- **渲染**：每帧取可见区快照（见上），合并相同背景的连续格子为矩形，按样式把文字分段排版；格子宽度取字体的 `advance`，宽字符占两格；粗体、斜体、下划线、删除线、反色、暗淡；块状 / 竖线 / 下划线光标与闪烁；搜索、关键字高亮、OSC 8 与网址识别的链接。
- **吞吐**：解析在后台线程，界面最多每帧重绘一次；加入与旧版相同口径的性能基线（大量输出吞吐、按键回显延迟）。
- **shell 集成**：引擎线程扫描 OSC 133 / 633 / 9 / 777 / 7（不改变交给内核的字节），按标记的位置把一批输出切开分段解析，在 B 处记下光标、到 C 时从网格读出命令（633;E 给出时用它）；没有 shell 集成时按回车推断（旧版规则：等回显换行再读，提前输入、全屏程序中的、Ctrl+C 放弃的不记）。事件经 `EngineEvent::Shell` 送给界面：命令历史、长命令结束与程序请求的通知、登录后命令等提示符。
- **命令补全提示**（`suggest.rs`，默认关）：只在 shell 集成认出的输入区中给出——收到过 B、还没有 C，用户在这个提示符后输入过、没有按回车，主屏幕，光标在 B 所在的逻辑行上且之后没有文字；从 B 读到光标（保留末尾的空格）就是已输入的内容（`TerminalEngine::snapshot_with_prompt_input`：引擎线程随快照一起读出，与快照一致）。来源由使用方给（`CommandSuggestions`，新的在前），桌面端是本机加密保存的这台主机的命令历史：每个终端 Tab 在后台读出、解密，记下命令后与每个提示符开始时先比较历史的版本（`history::revision`：条数、行 ID 之和、最近的时间，不用解密），变了才重读，记录与读取排成一队。提示不进网格：每帧按快照排到光标后的空白格子上（与终端排字的规则相同：到行尾接下一行，宽字符放不下时换行，遇到有字的格子就停），颜色是前景与背景的混合；块状光标盖住的第一个字画成光标下的文字。→、End（在按键监听器中判断）接受整条，Ctrl+→ / ⌥→（终端视图的快捷键表中的 `AcceptSuggestionWord`，没有提示时让出给按键编码）接受一个词，接受的部分作为键入写给远端；回显到达之前连按时按“应有的内容”算，不会重复发送。
- **输出旁路**：`TerminalEngine::set_output_observer` 在引擎线程上每段输出调用一次，在这一批发布之后（不复制数据）。会话日志（自己的后台线程写盘，去掉控制序列、每行带时间、全屏程序的画面不记、单个文件 100 MB）、会话录制与 sudo 密码提示检测共用一个旁路（`termlet-desktop` 的 `output_tap`），检测到的变化经通道送回界面线程。
- **会话录制**（`termlet-core` 的 `recording`）：写成 asciicast v2（`.cast`，asciinema 能回放），头部只有宽高、开始时间、标题（主机名）、`TERM` 与配色，不写其他环境变量；事件为输出 `o`、大小变化 `r`（由包在传输输入端外的一层在引擎改大小时记下，与输出同一个队列，顺序不乱）、可选的输入 `i`（默认不录，设置开启后只记视图的 `write_input`：键入、粘贴、同步输入，代填的 sudo 密码与终端的应答不记）。输出在任意位置切开，被切开的多字节字符留到下一段（`Utf8Stream`）。开始时先写当时的屏幕（`TerminalEngine::screen_dump_then`：引擎线程在两段输出之间取屏幕快照写成控制序列，等界面把录制接到旁路上再接着解析，不重不漏），回放从录制开始时的画面接上。后台线程写盘，每批写完就刷进文件，异常退出时最后一行可能不完整，读入时跳过；单个文件 256 MB；停止、关闭 Tab、会话结束（含断线）、退出程序（`recording::stop_all`）时写完关闭。主机可设“连接后自动录制”。
- **回放**（`termlet-desktop` 的 `replay`）：读入 v1 / v2 / v3，事件时间统一成从开始算起的秒数；回放引擎 `TerminalEngine::replay` 不接传输，输出与大小变化由 `ReplayFeed` 按顺序送进来，在回放引擎自己的引擎线程上走与实时终端相同的解析（扫描器、同步更新），应答丢弃；视图的回放模式（`TerminalView::set_replay`）只读、网格按录制的大小（放不下时缩小字号）。进度（`recording::player`）：倍速 1× / 2× / 4×，跳过长停顿（超过上限的停顿缩短为上限）；往后跳把中间的输出接着送进去，往前跳另建一个回放引擎从不晚于目标的最近一份关键帧（没有时从头）送到目标位置，解析完再换上（不闪空白，拖动进度条时只保留最新的目标）；往后跳得很远、中间有关键帧时同样从关键帧开始。关键帧（`replay/keyframes.rs`）：一路放过去时每送过 4MB 输出、在控制序列的边界上（从最后一个 ESC、CAN、SUB 往后用一个小状态机判断）请引擎线程存一份（`ReplayFeed::checkpoint`），内核的状态不能拷贝，存的是引擎自己写成的控制序列（`dump::checkpoint`：回滚与屏幕、在备用屏幕中时连同主屏幕，格子连同下划线的颜色与超链接（OSC 8，带原来的 ID），以及画面之外接着解析要用的状态——滚动区域、DECSC 存下的光标、字符集、制表位、原点 / 自动换行 / 插入 / LNM 模式、等着换行的光标、之后写字的样式（含下划线颜色与开着的超链接）、光标形状、程序改过的颜色，还有 shell 集成记下的命令位置：写成同样的 OSC 133 / 633 标记，输入开始处的 B 写在原来的格子上（在备用屏幕中时按主屏幕上的位置），见过的标记、执行中的命令、633;E 给出的命令行照样接着用；alacritty 不给读的滚动区域、制表位与正在用的字符集由后端临时改动网格探出，再原样放回），新引擎解析它就回到当时的样子；同步更新中途不存。全部关键帧合计超过 64MB 时隔一份删一份、间隔加倍。配色：文件头里有配色（`theme`）时默认用它，回放 Tab 上可切换成当前的终端配色。
- **关键词高亮**：设置中的规则编译一次，所有终端共用同一个高亮器（`Arc`，渲染按它的指针缓存匹配结果）；按逻辑行匹配（折行拼起来），只给程序没有着色的格子换色，颜色取当前配色中保证对比度的那一组。

## 9. 界面

- 窗口：自绘标题栏（gpui-kit `TitleBar`），左侧栏（主机、本机、密钥、转发、快捷命令），中间是 `DockArea`（终端、SFTP、编辑器、设置都是 Tab，可分屏），右侧主机工具栏，底部状态条。
- 组件一律用 gpui-kit 现成的，先读 `.claude/skills/` 下 gpui-kit 的 Coding Guides 与 Design Guides；不凭记忆臆造 API，以 `~/.cargo/registry/src/*/gpui-component-0.8.1/` 的源码为准。
- 文案：`crates/termlet-desktop/locales/*.yml`，每个键下简体中文（zh-CN）、英文（en）、繁體中文（zh-TW，台湾用语，用语与格式见 [繁体中文用语](繁体中文用语.md)）、日文（ja）、韩文（ko）（用语、语气与标点见 [日文韩文用语](日文韩文用语.md)）并排；简体中文为源语言，其余语言同步；键说用途（`host.dialog.title_new`），一句话一个键，不拼片段。`i18n.rs` 的测试检查各语言的键与插值一致、繁体与日文不用 “”、韩文不夹汉字与全角标点。
- 界面语言：设置中可选跟随系统、简体中文、繁體中文、English、日本語、한국어。跟随系统时，写明繁体（`zh-Hant…`）或地区为台湾、香港、澳门的中文用繁体，其余中文用简体，日文、韩文用日文、韩文，其他语言用英文，读不到时用简体。语言代码同时交给 gpui-kit（rust-i18n 的 locale 全进程共用）：它的 zh-TW 缺 37 条，缺的退回英文，都在 Termlet 没用的差异视图（`Diff.*`）与时间选择（`DatePicker.time`）中；它没有日文、韩文，由 Termlet 的 `locales/gpui_kit.yml` 以 `gpui_component.` 开头补上（`rust_i18n::extend!`，启动时装一次；差异视图没补，退回英文）。危险命令内置规则的说明在核心中，有简体、英文、繁体、日文、韩文五种；命令行工具 `termlet` 与它经核心输出的文字只有简体中文与英文（繁体系统下显示简体）。日期的写法：简体、韩文 `2026-11-03`，繁体、日文 `2026/11/03`。官网只有中文与英文，日文、韩文界面打开英文的页面；使用统计的 `lang` 接收端只认 zh-CN、zh-TW、en，日文、韩文界面记为 en。
- 界面字体：gpui-kit 主题的字体默认是系统的界面字体，中文的 Windows 上是微软雅黑一类：日文的汉字照样显示得出来，却是中文字形。日文、韩文界面把主题的字体换成这种语言的（Windows 的 Yu Gothic UI / Meiryo UI、Malgun Gothic，macOS 的 Hiragino Sans、Apple SD Gothic Neo，Linux 的 Noto Sans CJK JP / KR，取第一个装了的，都没装时不变），切回其他语言时恢复系统的界面字体（`appearance::apply_ui_font`）。终端的后备字体同样按界面语言把日文、韩文字体排到中文字体之前（`termlet_terminal::fonts::fallbacks`）。
- 换行（`prose`）：中文、日文按避头尾规则（日文另有小写假名、长音“ー”、叠字符号的行首禁则）；韩文以空格分词，在韩文字母与紧挨着的非空白字符之间不断开（同 CSS 的 `word-break: keep-all`），一个词比整行还宽时才从词中间断开（仍按避头尾）；断点处的空格留在上一行的行尾。
- 主题：gpui-kit 的浅色 / 深色加 Termlet 自己的界面配色；终端配色独立（内置 26 套，来源与许可随包附上）。
- 界面大小（`ui_scale`，本机设置 `window.uiScale`，0 为跟随系统，档位 90%–150%）：设 gpui-kit 主题的字号（`Root` 每帧把各窗口的 rem 设为它），按 rem 写的界面一起缩放，终端网格按自己的像素字号不受影响。跟随系统只在 Windows 上有来源（`HKCU\Software\Microsoft\Accessibility` 的 `TextScaleFactor`，与 DPI 无关，启动与窗口激活时重读；`TERMLET_TEXT_SCALE` 可代替读数）；macOS 没有全局设置，Linux 上 GNOME 的 `text-scaling-factor` 在 X11 下已并入 GPUI 读的 `Xft.dpi`，都按 100%。侧边栏、主机工具面板记下的宽度按 100% 记、用时乘上倍数；gpui-kit 写死像素的标题栏高度改用 rem，页签高度写死，所以最大 150%。
- 快捷键：可自定义的动作（核心 `keymap` 的动作表、默认值、校验与冲突）由界面按设置注册。GPUI 只能追加绑定，改掉的组合追加一条同组合的 `Unbind(原动作)` 只解除原来的那个动作；组合经键盘映射注册（`KeyBinding::load(…, cx)`），Windows 上 GPUI 把 Shift 加数字、符号键报告为 Shift 之后的字符，映射后 `alt-shift-=` 才按得出来。固定的快捷键用 `KeyBinding::new` 写明 `ctrl-` / `cmd-`（gpui-pre 0.3.10 起它不认 `secondary-`）。快捷键按系统分两套：核心的默认值按 `KeyOs`（Windows、Linux 用 Ctrl；macOS 照 Terminal.app、iTerm2 用 ⌘，Ctrl 组合交给终端，Option 输入组合字符），改过的快捷键也按平台分开存（macOS 用 `mac_bindings`，Windows 与 Linux 共用 `bindings`，同步后各用各的），固定的快捷键由各模块的 `key_bindings(os)` 给出、`init` 按当前系统注册，在 Windows 上也能逐张测三个系统的表；显示用核心的 `KeyCombo::label(os)`（macOS 上 `⇧⌘C` 这样的符号写法）。终端不把 ⌘ / Win 组合写进去。
- 粘贴：终端 Tab 用 `capture_action(Paste)` 先于终端视图处理所有粘贴（快捷键、右键、菜单），做粘贴前检查（控制字符一律去掉，会执行的多行、危险命令、`curl | sh`、看不见的字符、同形字先确认），剪贴板中是图片时保存到本机临时目录或经 SFTP 上传到服务器的 `~/.cache/termlet/paste` 后粘贴路径。
- SFTP：核心的 `SftpManager` 是应用级的（`AppState`），会话与传输记录按窗口区分（`owner`），窗口关闭时 `close_owner`。面板与它打开的编辑器共用一个 `SessionLease`，最后一个放下时关闭会话。传输列表经 `watch_transfers` 推送，一批结束经 `events()` 的 `BatchEnded` 弹汇总；跟随终端目录先用 OSC 7（终端视图的 `working_directory`），没有时每 2 秒经 `TerminalCwd` 查询。文件列表是自己的虚拟列表（gpui-kit 的 DataTable 只能单选），拖放用自己的 `DraggedFiles` 与 GPUI 的 `ExternalPaths`，`can_drop` 决定接收哪边拖来的。在线编辑器用 gpui-kit 的代码编辑器，语法高亮经 gpui-kit 转出的 `tree-sitter-*` 特性打开（只编进用得到的语法）。
- 多窗口与 Tab 移到别的窗口（`workspace/move_tab.rs`）：每个窗口一个 `Workspace`（根视图），打开着的窗口登记在一张表里（屏幕上的位置、最近到前台的先后）。移动的是面板实体本身：从原来的 `DockArea` 取下（实体由移动的一方拿着，不会关闭），放进目标窗口的 `DockArea`。gpui-pre 的 `subscribe_in`、`observe_in`、`defer_in` 与 `spawn_in` 任务中的 `update_in` 按实体“当前所在的窗口”（最近一次画出它的窗口，`App::with_window`）执行，面板在新窗口画出后自动跟过去；真正绑在登记时窗口上的——焦点的监听（`on_focus`、`on_blur`）、窗口的观察（激活、可见性）、`observe_global_in`、`spawn_in` 任务自己的窗口（对话框的队列）与 gpui-kit 输入框内部的焦点处理——由各面板的 `rebind_window` 在新窗口中重新登记或重建（路径框、查找栏重建，编辑器的编辑区照用、补登获得焦点时开始闪烁光标，以保留撤销记录）；连接时的询问换成新窗口的询问入口。SFTP 的会话与它的传输记录经 `SftpManager::reassign_owner` 改属新窗口（还没结束的传输移进新窗口的一批），原来的窗口关闭时不再关闭它们。跟着 Tab 走的还有：共用移走的终端的连接的端口转发（`ForwardManager::reassign_group`，按连接组）、单独移走的编辑器用着的 SFTP 会话——原来的窗口里不再有用着它们的 Tab 时改属新窗口；还有时留在原来的窗口，原来的窗口关闭时（工作区的 `on_release`，在 `Drop` 的清理之前）交给还在用它们的窗口（`SftpManager::hand_over` 只换会话的所属窗口，原来窗口在它上面的传输照常取消）。编辑器在别的窗口中要求文件管理重新连接时，询问在编辑器的窗口中弹出；会话的自动重连不询问（只用打开时输入过的密码）。终端、SFTP 正在连接时不能移。拖出窗口：按下鼠标后窗口捕获指针（Windows 的 `SetCapture`），拖到窗口外仍收得到移动与松开，工作区根元素的 `on_drag_move` 跟着 Tab 的拖动，按指针的屏幕位置找它所在的另一个窗口（叠在一起时取最上面的：系统给得出前后次序时按它，否则按最近到前台的），`on_mouse_up_out` 时移过去或在松开的位置新开窗口；窗口里只有一个 Tab 时停靠区不让拖动它，换成停靠区不接受的载体，只能拖到另一个窗口上。GPUI 的拖动预览只画在窗口之内，窗口外的提示画在窗口边上。
- 竖排 Tab（`workspace/tab_list.rs`，本机设置 `window.tabPosition` 为 `left`）：停靠区照旧管理窗格与 Tab（布局、拖动分屏、保存为工作区不变），只换外观。`dock_skin` 的 Tab 分组渲染（`TabGroupRenderer::render_tab_bar`）读一个由工作区每帧写入的开关（`TitleOnly`），竖排时不画横排的 Tab 栏，改画一条细标题（显示着的 Tab 的 `title`，拖动、中键关闭、接受别的窗格拖来的 Tab 与横排的 Tab 相同）。列表是工作区自己画的一列：每帧从 `DockArea::layout(Center)` 读出各窗格（`PaneRef::Tabs` 的面板与 `active_ix`）与面板，按布局树的分割比例算出各窗格的位置来起名（说不清或重名时编号）；每行画什么由各种 Tab 的 `tab_face` 给出（图标、窄栏用的大一号图标、名称、状态与按主机分组的键，状态与横排的标题共用同一段代码；另有状态的颜色与说明 `TabStatus`，最要紧的在前，窄栏在图标角上画第一个、悬停提示逐条写明）。点击走工作区原有的 `show_terminal` / `show_sftp` 等；右键先切到那个 Tab（菜单中的动作派发给显示着的面板），菜单用面板自己的 `dropdown_menu`；拖动用停靠区的 `DragPanel`（窗口里只有一个 Tab 时用 `SoleTabDrag`），放在行上按上半 / 下半算出位置后调 `DockArea::move_panel`，所以拖到内容区分屏、拖出窗口沿用原来的处理。窄栏上悬停时浮出的列表是窄栏的绝对定位子元素，放在窄栏的右边（不盖住窄栏），经 `deferred` 画在终端之上（优先级低于菜单），不占布局；指针在窄栏或列表上、从列表打开的右键菜单还拿着焦点、或列表有键盘焦点时不收起。宽度、收起状态与按主机分组时折叠着的主机记在界面状态（`tabListWidth`、`tabListCollapsed`、`collapsedTabHosts`，宽度按 100% 界面大小；折叠按主机的键记，与主机工具记页相同的做法，最多 100 台），窗口放不下展开的列表（最窄时也给主区域留不出 400 的宽度）时自动用窄栏。键盘：列表本身跟踪焦点（上下文 `TabList`，固定的快捷键 ↑ ↓ Home End Enter Delete ← → Shift+F10 / 菜单键 Esc，macOS 另有 ⌘⌫），入口是可自定义的“焦点进 Tab 列表”（默认没有快捷键）、命令面板与点列表的空白处；各行按下鼠标时 `prevent_default`，点行切换后焦点在那个 Tab 上、不经过列表。当前行记成 Tab 或主机标题，那一行不在了时按位置就近；用键盘打开的菜单与 SFTP、主机工具的列表一样放在当前行下面，关掉时没选菜单项就回到列表。
- 关闭：Dock 没有关闭前的钩子，Tab 标题上用自己的关闭按钮（与 Ctrl+Shift+W、菜单中的“关闭”），有连接时按设置先确认；关闭窗口用 `on_window_should_close` 确认。本地终端的 ConPTY 与进程在后台线程上创建（在界面线程上创建时 Windows 会在其间回调窗口，而应用正被这次点击占用）。

## 10. 命令行工具

命令、输出（终端里是可读文本，被捕获时是 JSON）、退出码 0–7、安全模型（默认关闭、按主机授权、CLI 专用凭据、危险命令规则加界面审批、审计日志）全部沿用旧版第 6 章；协议是带长度前缀的 JSON 消息，第一条消息协商版本。`termlet` 只链接 `termlet-proto`，体积小、启动快。

`termlet mcp`：标准输入输出上的 MCP 服务，由 AI 工具（Claude Code、Claude Desktop、Cursor、Codex 等）按配置启动，不开端口（HTTP / SSE 传输以后再说）。工具与命令一一对应（`list_hosts`、`run_command`、`upload_file`、`download_file`），每次调用照常连 CLI 服务、发同样的请求：开关、按主机授权、危险命令与批准、审计都在应用端，MCP 不另做一套，审计的调用方前面加 `mcp:<客户端名>`。JSON-RPC 手写（serde_json），不用 rmcp 等 SDK：只用到 tools 一项能力，`termlet` 保持小、不引入异步运行时。同时支持规范 2026-07-28（每个请求的 `_meta` 带版本，`server/discover`）与以 `initialize` 握手的 2025-11-25 及更早的版本。业务上的失败是工具执行错误（`isError`，带错误码）；执行结果给 AI 的输出合计最多 32KB（保留开头与结尾）；`notifications/cancelled` 关闭到应用的连接，应用中止这次请求（Windows 上用 `CancelIoEx` 取消同步的管道读写）。设置“命令行工具”页给出各 AI 工具的配置片段（`termlet-proto` 的 `mcp` 模块）。

## 12. 打包、更新与平台

- 三个平台随 0.1.0 一起发布（2026-10-30 用户定；原定 macOS、Linux 只作实验版）：Windows x64（安装向导）；macOS arm64（ad-hoc 签名的 `Termlet.app`，zip，macOS 11 起；没有 Apple 开发者证书、不公证）；Linux x64（tar.gz，Debian 12 中构建，要求 glibc 2.35 以上）。只有 Windows 设备可人工测试，macOS、Linux 没有真机测试，代码保持可移植。
  - arm64（2026-11 起，实验版）：Windows arm64（安装向导与便携版，`-win-arm64.exe`、`-win-arm64-portable.zip`）与 Linux arm64（`-linux-arm64.tar.gz`、`.deb`、`.rpm`、`.AppImage`），包的内容、打包方式与 x64 相同。没有 arm64 的真机：只在 GitHub Actions 的 arm64 运行器（windows-11-arm、ubuntu-24.04-arm）上原生编译、跑核心测试（`arm64.yml`），README 与官网写明是实验版。Windows 的安装程序（NSIS 只有 32 位的）按 `ARCH` 区分安装前的检查：arm64 的只能装在 arm64 的 Windows 上（`IsNativeARM64`）；两种安装包装到同一位置、写同样的注册表项，可以互相覆盖。x64 的程序在 arm64 的 Windows 11 上经仿真运行时仍按 x64 更新（架构按编译时定）。Linux arm64 在同一个多架构的 Debian 12 镜像中构建，`package.sh` 打包前核对程序的 ELF 架构与用到的 glibc 符号不高于 2.35。`release.mjs build --arch` 核对程序 PE 头中的机器类型，暂存目录 x64 是 `stage`、arm64 是 `stage-arm64`。
  - 应用的 ID `dev.termlet.Termlet`：macOS 的 Bundle ID；Linux 上设为窗口的 app_id（Wayland 的 xdg-toplevel app_id、X11 的 WM_CLASS，GPUI 的 `WindowOptions::app_id`），与菜单项 `dev.termlet.Termlet.desktop` 的文件名、`Icon=`、`StartupWMClass=` 相同，桌面环境据此显示名称与图标（X11 的窗口图标 `WindowOptions::icon` 要直接依赖 image，没有设）。
  - 图标都从 `docs/brand/logo.svg` 渲染（`packaging/render-icons.mjs`）：macOS 的图标集 `packaging/macos/Termlet.iconset` 在 CI 中用 iconutil 生成 `Termlet.icns`（Info.plist 的 `CFBundleIconFile`）；Linux 按 hicolor 主题的 16–512 共 8 种 PNG 加上 scalable 的 logo.svg，放在 tar.gz 的 `share/icons`。
  - Linux 的 tar.gz：根部是 `Termlet`、`bin/termlet`，`share/` 下是菜单项与图标，`install.sh` 把菜单项（Exec 改成解压目录中 Termlet 的完整路径）与图标装进当前用户的 XDG 数据目录、把命令行工具链接为 `~/.local/bin/termlet`（不需要 root，`--uninstall` 卸载），`README.txt` 说明安装、依赖与更新。
  - Linux 另出 deb、rpm、AppImage（0.2.0 起，`packaging/linux/package.sh` 从 tar.gz 的暂存目录打出）：deb、rpm 用 nfpm（`nfpm.yaml`；程序在 `/opt/termlet`，`/usr/bin/termlet` 链接到命令行工具，菜单项与图标在 `/usr/share`，依赖按 deb 的包名、rpm 的 soname 写，没有维护脚本，卸载由包管理器删干净）；AppImage 用 appimagetool 与固定版本的 type2 运行时（运行时静态链接了 libfuse 等，许可随包放在 `licenses/appimage-runtime.txt`），`AppRun` 按调用的名字运行 Termlet 或命令行工具（链接为 `termlet` 时是命令行工具，拉起 Termlet 时运行 AppImage 本身）。工具在 CI 中固定版本、核对 SHA-256，不进 Rust 依赖。
  - Windows 便携版（0.2.0 起）：`release.mjs build` 打完安装包后从同一个暂存目录另打 `termlet-<版本>-win-<架构>-portable.zip`（顶层 `Termlet\`：Termlet.exe、`bin\termlet.exe`、licenses、许可说明、`portable.txt`），作为这个架构的清单（`latest.yml` / `latest-arm64.yml`）的第二项（`path` 仍是安装程序，客户端只按 `-win-<架构>.exe` 取安装包）。程序旁有 `portable.txt` 时数据在程序旁的 `data\`（规则在 `termlet-proto` 的 `endpoint::data_dir_for`），只提示更新、不改 PATH。以后有代码签名证书时，先签暂存目录中的程序再 `build --stage`，安装包与 zip 一起重打。
  - 更新：macOS、Linux 读各自的版本描述文件 `latest-mac.yml`、`latest-linux.yml`（格式与 Windows 的 `latest.yml` 相同，列出 zip / tar.gz，Linux 的再依次列出 deb、rpm、AppImage，path 仍是 tar.gz；签名的可信注释带文件名，不能拿别的平台的清单冒充），校验签名后只提示新版本、打开官网的下载页，不下载、不安装。
  - 清单按架构分开（`update::manifest::metadata_file_for`，与 `release.mjs` 的 `manifestName` 相同）：x64 沿用最初的 `latest.yml`、`latest-linux.yml`，内容也只列 x64 的包（已发布的 x64 客户端读它们，行为不变；官网按扩展名从清单中取包，不会混进别的架构的）；其他架构在文件名后加 `-<架构>`：Windows arm64 读 `latest-arm64.yml`（安装版据此自动更新，只取 `-win-arm64.exe`），Linux arm64 读 `latest-linux-arm64.yml`。macOS 只有 `latest-mac.yml`。可信注释带文件名，x64 的清单冒充不了 arm64 的；没有发布这个架构的清单时报“未发布”，不会退回去取别的架构的包。“前往下载”按包与架构定位到下载页的一节（arm64 的 `#install-win-arm64`、`#portable-arm64`、`#linux-arm64-deb` 等）。
  - 命令行工具：只在 Windows 上由 Termlet 加入 PATH；其他平台设置中给出手动链接的命令。经符号链接运行时按链接指向的位置找 Termlet（macOS 上 `current_exe` 是链接本身的路径）。
- 安装程序沿用旧版的安装向导行为：许可页、可改安装位置（默认 `%LOCALAPPDATA%\Programs\Termlet`）、只为当前用户安装、不需要管理员权限。用 NSIS 脚本直接打包。向导按系统语言显示简体中文、繁體中文、English、日本語或한국어（NSIS 自带的语言文件）；许可页的说明只有简体、繁体、英文三版（后面接英文的 AGPL 全文），日文、韩文系统上显示英文版并在许可页上方说明，不做机器翻译。
- 自动更新：签名的版本清单（minisign，复用旧版的公钥槽位设计），下载、校验后在退出时静默安装，点“重启并安装”时安装程序只显示一个进度窗口（“正在更新 Termlet”，装完自动关闭并重新打开；Termlet 照旧传 /S，安装程序见到 --updated --force-run 时改回显示，已发布的版本升级时也有）；`TERMLET_UPDATE_URL` 可改更新源或关闭。
- 使用统计（`termlet_core::usage`，界面在 `usage_ui`；方案见[使用统计方案](使用统计方案.md)）：
  - 发送条件：设置“发送匿名使用统计”开着（本机设置 `usage.enabled`，默认开；不另外提示，安装包许可说明的第四节、官网的隐私说明与设置“关于 → 隐私”中写明，用户 2026-10-29 定）；不是调试构建；没有被环境变量或远程配置关掉；今天（UTC）用过（窗口获得焦点、处理命令行工具的请求）；今天还没有发送成功。主窗口显示时、每小时（与检查更新共用定时器）、新的一个 UTC 日第一次用到时检查，应用锁锁着时不检查；在核心的运行时上发送，不阻塞界面。
  - 正文：`POST https://api.termlet.dev/v1/stats`，9 个字段 `v`、`app`、`os`、`osVersion`（Windows 为 `11 25H2` 这类，不含构建号；macOS 按 Darwin 内核版本推算大版本；Linux 为白名单内的发行版与版本号，其余为 `other`）、`arch`、`lang`、`age`（`new` / `w1` / `m1` / `m6` / `old`）、`firstOfWeek`、`firstOfMonth`；没有 ID、时间与时区，国家或地区由接收端另记。“查看发送的内容”显示的与发出的由同一个函数生成；每次发送成功在日志中写一行原文。
  - 失败：网络错误、10 秒超时、5xx、408、429 留到下一次检查；其他状态码（含 3xx，不跟随重定向）当天不再试；不补发前一天的。
  - 关闭：设置中关掉（保存后）删除 `usage.json`，正在进行的那一次发送成功后也不再写它；`DO_NOT_TRACK`（`0`、`false` 以外的值）或 `TERMLET_USAGE_URL=off` 时开关显示为关、不能改；`TERMLET_USAGE_URL=<地址>` 改接收地址（调试构建只接受本机回环地址，测试用）；远程配置的 `usageUrl` 为 `off` 或空字符串时所有客户端停发，为其他地址时只接受 `https://api.termlet.dev/` 下的（远程配置不可用时照样用内置地址）。命令行工具 `termlet` 不发。
- 发布构建：`lto = "thin"`、`codegen-units = 1`、去符号（三个平台相同）。
- 构建与发布（2026-11-11 起在公开仓库 termlet/termlet 的 GitHub Actions 上，原先签名与发布在本机）：
  - 准备：`scripts/release.mjs prepare <版本>` 改 `Cargo.toml` 的版本号（连同 `Cargo.lock` 中本工作区的包），把 `CHANGELOG.md` / `CHANGELOG.en.md` 最上面“未发布”的一节改成版本号与日期，提交后推送标签 `v<版本>`。更新日志只写在这两个文件中：平时每做完一项用户能感受到的改动就写进“未发布”一节。
  - `release.yml`：`check` 核对标签、版本号与更新日志（这一版还是“未发布”时在这里失败）→ Windows 的全量测试与连 sshd 的测试 → 各平台打包（Windows、Linux 的 x64 与 arm64 用同一个 job 的两种架构，各在自己架构的运行器上原生编译，arm64 先跑核心测试；arm64 是实验版，它的 job 失败不算运行失败，`continue-on-error`）。这些 job 只有读权限，不接触任何秘密，依赖的构建脚本只在这里运行。
  - 签名与发布（`release` job，只在推送标签时）：GitHub Environment `release`，要用户在网页或手机上批准（Required reviewers）才运行；Secrets 只在这个环境中（只存一份），环境的部署规则是 `v*` 标签加 main 分支（main 给远程配置的工作流用，这个 job 的 `if` 只认推送的 `v*` 标签；把关的是每次进环境都要的批准，推送 main 的只有维护者，fork 的合并请求在 `refs/pull/…` 上进不来）。只下载上一步的产物（zip 原样），不运行 npm / pnpm install 与 cargo，只运行 `release.mjs`（只用 Node 自带的模块）与运行器自带的 unzip、gh：`collect` 在碰任何秘密之前，先用构建 job 经 job 输出报告的摘要（upload-artifact 的 `artifact-digest`）核对每个 zip 的 SHA-256，再解开核对各平台、各架构的包与清单齐全、版本与标签一致（arm64 缺了时警告，这一版不出那个 arm64 的清单与包，下载站上原有的不动）→ `sign` 用在用的密钥给更新清单与 SHA256SUMS 签名（私钥由这一步写进 `$RUNNER_TEMP` 下权限 600 的临时文件，下一步 `if: always()` 删掉；口令从环境变量读，读过即从进程环境中删掉）→ `actions/attest` 给 SHA256SUMS 中的每个文件生成构建来源证明（`gh attestation verify <文件> -R termlet/termlet` 核对）→ `publish` 经 R2 的 S3 接口（只能读写桶 termlet-dl 对象的 R2 令牌；请求签名手写，AWS 签名第 4 版，`selftest` 用 AWS 的样例核对）先传各平台的包、最后传清单，经 Cloudflare 的接口清 CDN 缓存（只能清 termlet.dev 缓存的令牌），经 https 取回核对，在本仓库建 GitHub Release（说明取更新日志中这一版的中英文两节），最后调用 Cloudflare Pages 的部署钩子让官网重建（官网构建时读下载站上的清单与本仓库的更新日志）。签名与发布在同一个 job 中：环境审批按 job 算，分开要批准两次；每个秘密只放在用它的那一步的 env 中。
  - 密钥：在用的那把（70538B50651A6352）在 `release` 环境的 Secrets 中；离线备用的那把（1274237273808A74）只在仓库外离线保管、不进 CI，轮换时在本机用它签名（`keys.rs` 的说明）。
  - 远程配置：`packaging/remote-config/update.json` 是 `dl.termlet.dev/update.json` 的原文，改动提交到默认分支后手动运行 `remote-config.yml`（同样在 `release` 环境、要批准）：`sign-config` 签名（带签发时间与有效期，最长 366 天），`publish-config` 上传、清缓存、核对。
