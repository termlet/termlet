# Changelog

[简体中文](CHANGELOG.md) · **English**

This file lists the changes you will notice in each version, newest first. Versions follow [Semantic Versioning](https://semver.org/): before 1.0, a minor version bump (0.x) may bring incompatible changes, which are noted in that version. Each version's heading gives the version number and release date (changes not yet released go into a section marked "unreleased" at the top, which gets its date on release), and its changes are grouped into Added, Changed, Fixed and Security (empty groups are left out; the first version is summarized by area instead). Any change to the anonymous usage statistics collected is noted in the version that makes it. For downloading and installing, see [Installation](README.en.md#installation) in the README.

## 0.3.6 (2026-11-28)

### Added

- The portable version can remember its master password on this computer (issue #3): check "Remember on this computer" (unchecked by default) where you enter the master password, then unlock. A copy of the master key goes into this computer's Credential Manager (the master key, not the master password), and you aren't asked again when you open Termlet on this computer. On other computers you still enter the master password; several portable copies on one computer are told apart by their own data and don't affect each other, and it keeps working after you move the folder or change the master password. To stop, click "Forget" under Settings → Security and you're asked again next time. Resetting the vault removes it, and a remembered key that no longer matches the data (for example, the vault was reset elsewhere) is removed automatically and you're asked as usual. It stays on this computer and isn't synced or backed up; it isn't offered when no system keychain is available. The installed version and portable copies set to "This computer only" are unchanged.
- Detected local terminals can be edited and hidden (issue #7): under Settings → Local Terminals, the edit button on a row changes its name, arguments, starting folder and environment variables, and "Restore defaults" puts back what was detected. You no longer need to add a second terminal just to set a starting folder, so the menu doesn't get a duplicate. Ones you don't use can be hidden from the menu next to "+", This Computer in the sidebar and the choices for the default (except the one opened by default); WSL distributions can be hidden too. Changes stay on this computer and aren't synced; they're kept if the shell is uninstalled and apply again once it's back.
- Start in a given folder with the default local terminal (issue #6): `Termlet.exe -openfolder "D:\work"`, written the same way as for MobaXterm (`--open-folder` works too), on macOS and Linux as well. If Termlet is already running, the tab opens in the current window; a folder that doesn't exist is reported and nothing opens; if "Open at startup" is set to the default local terminal, it opens in that folder instead of a second one. On Windows, Settings → Local Terminals can add "Open Termlet here" to the File Explorer context menu (off by default; it only writes the current user's registry and is removed when you turn it off; on Windows 11 it's under "Show more options"). After you move the portable version, it follows the next time Termlet starts, and uninstalling the installed version removes it.

### Changed

- Hovering over a terminal or SFTP tab now shows what it's connected to, on a line of its own: `user@address` for SSH (with the port when it isn't 22), `address:port` for Telnet, the port and baud rate for a serial port (such as `COM3 · 115200`) and the distribution for WSL; SFTP opened as root has root after it. Horizontal tabs, the vertical tab list and its collapsed icons all show it, a title set by the program still appears, and local terminals don't get this line. Before, horizontal tabs only had a tooltip when the program had set a title.
- Lists, dropdowns, the settings pages and other areas whose content doesn't fit now always show a scrollbar, so you can tell at a glance there's more (such as the "Source" dropdown when importing hosts). Before, scrollbars followed the system setting and on Windows 11 only appeared while scrolling by default. The terminal's scrollbar is unchanged.
- The result of "Test connection" in the host dialog is no longer cut off: a long error (such as a proxy command's error output, or the two fingerprint lines at the end when a host key doesn't match) scrolls within its box, and a failure can be copied with the button next to it. Before, only about three lines showed and the rest couldn't be seen.
- When you test a new host that has no name yet, prompts such as the password and proxy-command confirmations name it by its address instead of showing an empty name (such as `Run the proxy command for "" on this computer?`); `%n` in a proxy command is the address too, as it is once the host is saved.
- The snippet bar scrolls sideways with the mouse wheel when its snippets don't fit, so the later ones can be clicked. Before, the wheel did nothing and the last button was cut in half.
- In SFTP, hovering over a truncated file name shows the full name (files that differ only at the end looked the same once truncated), and the path box shows the end of the path, so you can see which folder you're in; it scrolls back to the end after you click in and leave. Before, it showed the beginning and a deep path hid the current folder.
- Areas that could scroll but had no scrollbar now have one: the Tunnels, Keys, Profiles and Snippets lists in the sidebar, the pages of the host dialog, exporting, importing and editing color schemes, the host list when deploying a public key, the snippet picker, batch output, crash reports, host tool details, the collapsed vertical tab bar, and the page navigation on the left of Settings and the host dialog (narrow places get a thin scrollbar that doesn't cover the icons). Lists inside a dialog still scroll when the dialog is taller than the window, and exporting color schemes, deploying a public key, the snippet picker, the command palette and the color scheme picker shrink to fit the window. Buttons at the right end of lists and tables (such as closing a tab in the vertical tab bar, canceling an SFTP transfer or the process of a network connection) and right-aligned figures (CPU in the process table, exit codes in the audit log) make room for the scrollbar, so the thumb no longer covers them or catches their clicks.
- In a short window or at a larger interface size, long menus (terminal tabs, the terminal area, SFTP files, rows in the host tools, hosts and groups in the sidebar, and the local terminals and "More" menus in the title bar) shrink to fit the window and scroll, and dropdown lists stay inside the window too. Before, the last items ran off the bottom of the window and couldn't be clicked.
- Tabs with long names in the top tab bar cut the name short, with the full name on hover. When the tabs don't fit, the current tab stays in view after the window, the sidebar or a split gets narrower, and the end where more tabs are hidden fades out. Before, a host with a long name could take up most of the tab bar, narrowing the window pushed the current tab out of view, and nothing showed that there were more tabs on either side.
- Snippets can be reordered by dragging (issue #5): on the Snippets page in the sidebar, drag snippets to change their order, or into another group to move them there; drag group headings to reorder groups (Ungrouped always comes first). The snippet bar, the picker (Ctrl+Shift+Space) and exports follow this order, and sync carries it to your other computers. Nothing changes until you drag: groups stay sorted by name and snippets in the order they were added.
- Snippet groups can be renamed and deleted as a whole (issue #5): right-click a group heading or click the ⋯ that appears on hover. Renaming a group to the name of an existing one merges them and tells you so; when deleting, choose whether its snippets move to Ungrouped or are deleted too, with the number of snippets shown. When editing a snippet, you can pick an existing group from the dropdown next to the group box instead of typing a name.
- Hovering over truncated text shows all of it: names, addresses and groups in the import preview, the names, routes and target connection errors of tunnels in the sidebar, snippet names and groups, host group names, local terminal names, the names and command lines in Settings → Local Terminals, and options in dropdown lists.
- A terminal tab's context menu is down from 20 items to 11: splitting, sync input, moving to another window and saving as a workspace are under "Splits and Windows ›"; copying the IP address, revealing the host in the sidebar, command history, adding a port forward and lending the local proxy are under "Host ›"; session logs and recording are under "Logging and Recording ›" (along with "Open Recording…" to play one back). In an SFTP tab's menu, opening as root and opening in VS Code or Zed are under "Open With ›" (still listed directly when there are fewer than three). Shortcuts and the command palette work as before.

### Fixed

- In the host tools of a WSL terminal, the Docker page no longer shows "Failed to read containers: …/usr/bin/docker: Input/output error" after Docker Desktop has been started and quit; it says Docker is not running, as when Docker Desktop was never started. When docker in WSL comes from Docker Desktop (not started, started and quit, or WSL integration not turned on for the distribution), the next step is to start Docker Desktop on Windows and turn on WSL integration for the distribution, instead of `sudo systemctl start docker`, which doesn't apply.
- Long dialog titles (such as the proxy command confirmation for a host with a long name) no longer wrap under the close button in the top right.
- When a dialog pops up on its own (such as a question while connecting, or the confirmation when closing the window), a tooltip that was already showing (for a tab, a host, truncated text and so on) goes away instead of staying on top of the dialog; tooltips inside the dialog work as usual.

## 0.3.5 (2026-11-26)

### Added

- The SFTP local side can open WSL: the "Places and Drives" menu (the drive icon) lists your WSL distributions after the drives (the same ones as the menu next to "+" in the title bar, without Docker Desktop's internal distributions; three or more go into a "WSL Distributions" submenu). Choose one to open the default user's home folder in it and upload or download between WSL and the server directly, without installing sftp-server in the distribution. A distribution that isn't running is started only when you choose it, which can take a few seconds. In WSL, names starting with `.` count as hidden; Linux permissions, symbolic links and file names Windows doesn't allow can't be kept when going through Windows, so use the WSL file manager when you need them.
- Computers on the LAN can transfer files over MCP too: the AI over there calls `upload_file` or `download_file` with just the host and the path on the server, Termlet checks it and gives a one-time transfer link, and the AI sends or fetches the file with curl on its computer (`curl -T` to upload, `curl -o` to download). The file goes between that computer and the server through Termlet (over SFTP, or SCP when the server has no SFTP), never through the AI's conversation and with no size limit, and files on this computer stay out of reach. A link works once, for 10 minutes, and only from the computer that asked for it; host access and the audit log work as usual (source "MCP·LAN"), and an upload cut off halfway deletes its temporary file on the server, leaving the file there as it was. Before, computers on the LAN could only list hosts and run commands.
- Snippets can be exported: choose "Export Snippets…" under More on the Snippets page (where the "Import Snippets" button has moved too) or in the command palette, select groups (all by default; ungrouped snippets can be selected too) and save a JSON file (`termlet-snippets-date.json` by default) with each snippet's name, content, group and whether it runs after sending. The file is plain text, so passwords and anything else written in your snippets are saved as they are. On another computer, import it with "Import Snippets…" and the source "Termlet snippets (.json)", next to NyaTerm's; picking the wrong one still works, as the file is recognized by its contents. You get a preview as before, snippets with the same name and content as existing ones are marked "Exists" and not imported again, and parameters such as `{{name:default}}` and `{{.Names}}` stay as written. Before, only snippets exported from NyaTerm could be imported.

### Changed

- When opening SFTP, if the local side was last in a WSL folder and that distribution isn't running, it no longer goes back there (which used to start the distribution) and opens your downloads or home folder instead.
- When you use `termlet.exe` (the command-line tool on Windows) in WSL, local paths can be written the WSL way: in uploads, downloads, `--script`, `--input`, `--output-dir`, `-H @file`, `skill install --dir` and `local_path` in MCP, `/mnt/c/…` becomes `C:\…`, and `/home/…` and the like become `\\wsl.localhost\<distro>\…` when the current directory is inside WSL. An absolute path inside WSL given while the current directory is under `/mnt/…` is now a usage error that says how to write it, instead of being taken as a path on the current drive (`C:\home\…`, where batch downloads and `skill install --dir` used to quietly create folders and write). On Windows, all local paths starting with `/` follow these rules; `/tmp/x` used to mean `C:\tmp\x` on the current drive. The Agent Skill now explains how to use it in WSL, and the user guide has a new "In WSL" section.
- Batch run is easier to find: "Batch Run…" in the command palette also turns up for "multi", "compare", "batch", "run on hosts" and similar words, in any of the five interface languages whatever language the interface is set to; and the toolbar can have a Batch run button (hidden by default; tick it in the Toolbar section of Settings → General, or with "Customize Toolbar…" on a title bar button's right-click menu), which works like the command palette entry and starts by choosing hosts. "Batch Run…" is gone from the group context menu: tick the group in "Choose Hosts" instead, which picks the hosts in it, subgroups included.

### Fixed

- On Windows, when Termlet wasn't running and the `termlet` command or the MCP server (`termlet mcp`) started it in the background, the calling AI tool or script only got the result once that background Termlet exited (after 10 minutes without requests), so it looked stuck: Termlet had inherited the caller's output pipe. Calls now return as soon as the command finishes, and the background Termlet now runs in its program folder instead of holding on to the folder it was called from (which couldn't be deleted until it exited).

- Deleting on the local side in places without a Recycle Bin (network shares, mapped network drives, WSL, USB sticks and other removable drives) said "Move to Recycle Bin" but deleted the files permanently, with no way to get them back. These places now say "Delete Permanently" in the menu and that the items will be deleted permanently and can't be recovered; everywhere else items still go to the Recycle Bin, and if Windows can't move something there (for example, it's too large), nothing is deleted and you're asked whether to delete permanently, so nothing is deleted permanently without asking.
- Uploading a named pipe, device file or other special file no longer hangs: it's skipped and you're told such files can't be transferred (inside folders they're skipped as before). Such files in WSL look like regular files through Windows; the local side now recognizes them too, where it used to report a system error after about 20 seconds.

## 0.3.4 (2026-11-25)

### Added

- Batch run tab: run the same command on a set of hosts or open terminals and see the results merged. Open it with "Batch Run…" in a group's context menu (targets the hosts in the group, subgroups included) or in the command palette. With the Hosts target it runs over new connections without opening terminals (with the same credentials as a terminal; hosts don't need to be allowed for AI tools and scripts). "Choose Hosts" picks them by group, tag or search; Telnet and serial hosts can't be picked. Hosts whose fingerprint isn't confirmed yet, or that need a password or verification code typed in, are listed as unreachable, with "Open in Terminal" in the results. With the Open terminals target it runs in the terminals (needs bash / sh), with their current directory and environment, which is the way to reach hosts behind a bastion. The command can span several lines and you can insert snippets (filling in their parameters first); Ctrl+Enter (⌘↩ on macOS) runs it, and ↑ ↓ recall the commands run in that tab. Each target gets the same status words as the command-line tool (succeeded, failed, unreachable, timed out, canceled, not run), identical outputs are merged into one group, other groups show only the lines that differ from the first, and unsuccessful targets are listed with the reason; you can stop, retry the unsuccessful ones and copy the results. Terminals stay usable while it runs and the tab can move to another window; closing the tab or window while it runs asks first. The command is checked against the dangerous command rules once, and the confirmation says how many targets; the audit log gets an entry per target with the source Batch run and one batch ID per run.
- Batch runs in the command-line tool: give `termlet exec`, `upload` or `download` options that pick hosts instead of `<host>`, and the same command runs (or the same file is transferred) on a set of hosts at once, each over a new connection, with no terminals to open first. Pick hosts by group (`-g`, subgroups included; groups with the same name can be written as paths such as `prod/web`), tag (`-t`, which must also match the group), a list (`-H a,b`, or `-H @file` to read it from a file) or all of them (`--all`); `-x` excludes hosts, and `--list` only lists the hosts that would run or be skipped. Only SSH hosts allowed for AI tools and scripts are used, and the rest are listed as "not run" with the reason. Up to 10 run at a time (`-j` changes it, up to 64), `--timeout` limits each host's command (SIGTERM when exceeded), and `--max-fail` stops starting new hosts after that many failures. A progress line appears as each host finishes; at the end, hosts with the same exit code and output are grouped together (`--no-group` prints them one by one), the hosts that didn't succeed are listed with the reason, and a summary line counts failed commands and unreachable hosts separately. When piped, the output is JSON (`--json-lines` gives a line per host), and `--output-dir` writes an output file per host plus `summary.json` and `retry.txt` (`-H @retry.txt` reruns just the hosts that didn't succeed). While it runs, Ctrl+C lists the hosts that haven't finished, and pressing it again cancels them all. A dangerous command asks for approval once for the whole batch, and the dialog shows how many hosts and which; the audit log gets one entry per host, all with the same batch ID, and "Same batch" in the details filters to it. The new exit code 8 means some hosts didn't succeed. A batch download puts each host's file in a subdirectory named after the host. The protocol between the command-line tool and Termlet is now version 2: an older Termlet doesn't support batch runs, and the command-line tool asks you to update it.
- `termlet exec` gets `--script <file> [-- args…]`, which feeds a local script to the remote shell over stdin (the `#!` line picks bash, sh and so on), with arguments and without leaving the script on the server; it's checked against the dangerous command rules too. `--input <file>` sends a local file to the remote command's stdin (for example `--input nginx.conf "sudo tee /etc/nginx/nginx.conf"`). Both work for one host or a batch.
- Settings can be searched: the search box above the categories (Ctrl+F, ⌘F on macOS) filters by page name and by the titles and descriptions of settings, lists only the pages with matches along with how many, and highlights the matching settings, expanding collapsed sections, switching tabs and scrolling to the first match. Text in all five interface languages matches, so typing "字体" finds Font even with the English interface; with several words separated by spaces each one has to match, and Esc clears the box. The Shortcuts page has its own search box that filters by action name or key (such as ctrl+shift+c) and expands the fixed shortcuts when a row there matches; a search in Settings that finds shortcuts carries over to it.
- New MCP tool `run_command_on_hosts`: an AI tool can run the same command on a set of hosts at once (picked by host, group or tag, with an optional time limit per host), and hosts with the same output come back merged, so dozens of hosts that agree take the space of one. Checks, approval and auditing work as for `run_command`, and computers on the local network can use it too.
- Programs in the terminal can copy text to this computer's clipboard (OSC 52): when pi, tmux, Neovim and the like copy on a server, the text lands in your local clipboard. Before, pi showed "Copied!" but the clipboard did not change. Writes are accepted only while the Termlet window is in front and that terminal has focus, and each one shows a notice in the top right, such as "web-1 copied N characters to the clipboard", with "View" to see what was written. Programs cannot read your clipboard (read requests get no answer), and at most 1 MB is accepted at a time; anything larger is not written and you are told why. It is on by default and can be turned off with "Let programs write to the clipboard" under Settings → Terminal → Behavior. Session replays never write the clipboard.
- Ctrl+C copies when text is selected (as in Windows Terminal) and then clears the selection; with nothing selected it still goes to the program as an interrupt. Ctrl+Shift+C and Ctrl+Insert work as before; on macOS copying stays ⌘C and Ctrl+C always goes to the program.
- The SFTP remote and local panes can filter the current folder by name: in the list press Ctrl+F (⌘F on macOS) or /, or click the magnifier at the right end of the Name column, and a filter box opens under the header. Only items whose names contain the text are shown (ignoring case); with `*` or `?` the text is a wildcard pattern for the whole name (such as `*.log`), and the box shows how many items are shown out of how many. The first match becomes the current row: Enter or ↓ returns to the list, and Enter again opens it. Select all, Shift selection, dragging, downloading and deleting only act on the items shown. Esc clears and closes the filter; changing folders clears it, while refreshing and uploading keep it. When the remote pane follows a terminal, the box has "Find in terminal", which puts a `find` command that searches the current folder and every folder under it by name into that terminal and switches to it (without running it, after anything already typed on the command line); press Enter to run it.

### Changed

- Settings now open as a tab in the main window instead of a pop-up dialog (issue #3): next to the terminal tabs, filling the tab area and growing with the window, so you can drag it beside a terminal or move it to another window. Each window has at most one; opening Settings again from the gear, the command palette or a menu switches to it and shows the page you asked for. Changes are still written only when you click "Save", and Settings stay open afterwards while the terminal next to them picks up the new font, cursor and colors, so you can keep adjusting; "Discard changes" goes back to what was last saved. With unsaved changes the tab name starts with "●", closing the tab asks whether to save, discard or cancel, and closing the window or quitting includes them in its confirmation (closing the window used to drop changes in an open Settings dialog); a tab with unsaved changes can't move to another window. Ctrl+S (⌘S on macOS) saves; Enter in a text field no longer saves the whole page, and Esc no longer closes Settings. If settings change elsewhere while the tab is open (switching light / dark from the title bar, zooming from the command palette, cloud sync, another window), the tab follows along when you have no unsaved changes, and saving writes only what you changed, so it never puts the other change back. Passwords half-typed in Settings are cleared when Termlet locks. When the tab is narrow the categories on the left show only icons.
- Settings now have 12 pages instead of 14: Toolbar moved into General (as a section, collapsed by default), Color Schemes and Highlighting became Colors & Highlighting (two tabs), Host Keys moved into Security, and the privacy, diagnostics and log detail parts of About became Privacy & Diagnostics (About keeps the version, links, data folder and updates). Long pages are split into sections with the rarely used ones collapsed: Terminal has Appearance and Behavior, with Status bar and notifications, File transfers, Session logs and recording, and Command history and suggestions collapsed; on Connection, the ssh-agent address, X display and the local proxy lent to servers sit in one section; on AI & automation, the ways to connect (the termlet command, Agent Skill, MCP) and the 15 built-in rules are collapsed, the rules into one line that says how many are on; on Shortcuts, the fixed shortcuts are collapsed. "Customize Toolbar…" on a title bar button's context menu, the Keyword highlighting button in the toolbar and "Customize Toolbar…" and "Keyword Highlighting…" in the command palette still go straight there (opening that section or switching to that tab).
- Calls in the audit log that couldn't run (unreachable, host not allowed and so on) now show the result Error instead of Failed, so they aren't confused with batch-run failures, which mean a non-zero exit code. The Source filter has a new "Batch run" (runs in the Batch run tab).
- The compose bar's "Run and Compare" now shows its results in a Batch run tab (no more dialog, so the window stays usable while it waits) and is recorded in the audit log; running again in the same window reuses that tab unless it's still running.
- While sync input is on, snippets (from the snippet bar, the picker or the sidebar) go to every synced terminal, matching the banner that says keystrokes go to all of them, and are checked for dangerous commands like typing and pasting. Before, they went only to the current terminal.
- A snippet that would run and matches a dangerous command rule asks for confirmation first; cancel and nothing is sent. Snippets that are only typed, not run, aren't checked. Before, snippets skipped the dangerous command rules (the compose bar and sync input both checked them).
- In SFTP, a new folder or a renamed item is selected once it's created or renamed (if the filter would hide it, the filter is cleared first); before, the selection stayed where it was.
- Removed "Open SFTP on the Right" (from the terminal tab menu, the command palette, the macOS menu bar and the shortcuts): to put SFTP next to a terminal, open it and drag its tab onto one side of the terminal's content to split the pane. The command palette gains "Open SFTP File Manager for This Host", which works like the "SFTP" button in the title bar (a new tab sharing the terminal's connection and following its folder), even when that button is hidden. A shortcut you assigned to it no longer does anything and the key is free for other actions; your other shortcuts are unaffected.
- On Windows, local terminals and WSL now run through the Microsoft ConPTY that ships with Termlet (`conpty.dll` and `OpenConsole.exe` from Windows Terminal 1.25, next to Termlet.exe), which is newer than the one built into Windows: programs that use the mouse, such as vim, htop, tmux, mc and pi, now get clicks, drags and the wheel. Before, dragging only made a Termlet selection and the wheel turned into arrow keys in full-screen programs; hold Shift while dragging to select with Termlet instead. The portable package ships them too. If local terminals fail to open, delete the two files to go back to the built-in ConPTY (see "Local shells" in the user guide).

### Fixed

- In the sync input grid, the compose bar's "Current tab" also sent to terminals marked "Excluded"; it now sends only to the synced terminals.

### Usage statistics

- The feature list (`features`) has one more item, `batch_exec`: ran a batch (`exec -g` and the like on the command line, `run_command_on_hosts` over MCP, the Batch run tab including the compose bar's "Run and Compare"), 51 items in all.

### Security

- On Windows, Termlet now limits where DLLs loaded by name are searched to its own folder and System32 at startup: before, a DLL with the same name (such as `conpty.dll`) placed in the current folder or on PATH could be loaded (DLL planting).

## 0.3.3 (2026-11-22)

### Added

- The MCP server can now be reached over HTTP: under Settings → AI & automation, set the MCP server's transport to "HTTP" and turn on listening, and Termlet serves MCP on this computer at `127.0.0.1:47800` (the port can be changed); AI tools connect with the address and a token. It's off by default and only accepts connections from this computer (web pages in a browser can't connect); every request needs the token (Termlet checks it against a digest only, and you can regenerate it at any time); and since Termlet itself listens, it only works while Termlet is running. Claude Code, Codex, Cursor, VS Code (GitHub Copilot), Gemini CLI and generic JSON for other tools have configurations that include the token when copied and all go in user-level configuration; Claude Desktop can only use standard input and output. Tools, approval of dangerous commands and the audit log work as with standard input and output; the audit log's Source shows "MCP·HTTP (client name)" and records the process that opened the connection (Windows, Linux), and AI tools on a server can use it through SSH remote forwarding. It can also listen on "This computer and LAN": only connections from private ranges are accepted, with a separate LAN token that can be regenerated on its own; the other computer can only list hosts and run commands (it can't upload or download files on this computer), and the audit log and approval dialog show its address. Traffic on the LAN is unencrypted, so use it only on trusted networks; the settings page and user guide explain the risks, the Windows Firewall prompt, and encrypted alternatives such as SSH forwarding and Tailscale.
- Keyword highlighting: IPv6 addresses are now marked by default (full and `::`-compressed forms, zones such as `fe80::1%eth0`, `/64` prefixes, `::ffff:192.0.2.1`, and bracketed forms with a port such as `[::1]:22`; times, MAC addresses, certificate fingerprints and code such as `std::vector` are not mistaken for IPv6), added on upgrade if you never changed the rules. New "Add Preset": besides the defaults, you can add URLs, MAC addresses, UUIDs, dates and times, and numbers (with their units, such as `230ms` and `1.5GiB`); presets already in the list are checked, they're inserted in a fixed order (URLs first, numbers last) so URLs and dates aren't colored in pieces, a default rule deleted by mistake can be added back, and presets in the list show their name in front of the pattern. Colors can be customized: red, green, yellow, blue, magenta and cyan still take whichever is clearer in the color scheme (they look the same after the update), the new Dark Red and so on always use colors 1–6 of the terminal color scheme and Bright Red and so on colors 9–14, and "Custom Color…" picks any color with a color picker or a typed value, darkened or lightened automatically when it isn't clear enough on the background (contrast below 3:1); the swatches, menu and preview in Settings show the color as it actually appears on the current scheme. When synced to 0.3.2 or earlier, rules with a dark, bright or custom color are shown in red (the rules themselves are kept), and saving the settings in those versions changes their color to red.
- 13 new built-in terminal color schemes, 39 in total: One Dark Pro, Ayu Dark / Light, VS Code Dark 2026 / Light 2026, Monokai (VS Code) (the Monokai theme that ships with VS Code), Tomorrow Night, Catppuccin Frappé / Macchiato, Rosé Pine Moon, Nightfox / Dayfox and Kanagawa Lotus, each taken from the project's own files, with its source and license.
- SFTP online editing supports UTF-16 (LE and BE). Files with a BOM (text redirected with `>` in Windows PowerShell 5.1, .reg files, some Windows logs and exported CSV files) open directly, and files without a BOM are detected too when it's clear. Saving keeps the original encoding, BOM and line endings, and characters such as emoji are saved correctly. The status bar shows the encoding (such as "UTF-16LE BOM"), and "Reopen with another encoding" offers UTF-16LE and UTF-16BE. The encodings for host settings, terminals and SFTP file names are unchanged (UTF-8, GBK / GB18030, Big5).

### Changed

- MCP server and command-line tool: you now pick the AI tool for the MCP configuration from a drop-down, which adds VS Code (GitHub Copilot, in `~/.copilot/mcp-config.json`), Gemini CLI and generic JSON for other AI tools; Claude Code, Codex and Gemini CLI get both their `mcp add` command and the configuration file, each with its own Copy button. When a dangerous command comes from MCP, the approval dialog's title names the AI tool (such as "Claude Code (MCP) wants to run a dangerous command on …"; common tools by product name, others by the name they report), and tools without a brand logo get a generic AI icon; before, it always said "The command-line tool". ## 0.1.0 (2026-11-03)

The first public version, for Windows x64 (Windows 10 1809 or later), macOS (Apple silicon, macOS 11 or later) and Linux x64 (glibc 2.35 or later, such as Ubuntu 22.04 and Debian 12). The macOS and Linux versions haven't been tested on real hardware yet and don't install updates automatically (they tell you about a new version and open the download page); the macOS package is only ad-hoc signed and not notarized, so it has to be allowed under System Settings → Privacy & Security the first time.

### Connections

- SSH, Telnet and serial ports; quick connect by typing `user@address`.
- Authentication: password, private key (OpenSSH, PEM, PuTTY ppk), SSH Agent / Pageant, and interactive authentication when the server asks for it; verification codes (TOTP) filled in automatically.
- Profiles and group defaults, so many hosts can share one set of credentials.
- Multi-hop jump hosts (up to 5), SOCKS / HTTP proxies and proxy commands, agent forwarding, and support for old devices that only offer legacy algorithms.
- Host key verification; a notice when the connection stops responding, automatic reconnection, and resuming in tmux.
- After connecting, Termlet identifies the remote system (one read-only command in a separate channel, not through the terminal; skipped silently if it fails, and can be turned off under Settings → Connection) and shows the system's logo in the host list and on terminal and SFTP tabs.
- Can be opened by bastion hosts such as JumpServer and NSFOCUS OSMS.

### Terminal

- Tabs, split panes and workspaces, a command palette, and duplicate sessions (sharing the connection); a terminal tab always shows the name it was created with (the host name, the local shell and so on), with titles set by remote programs in its tooltip.
- Sync input, and a compose bar (send to many terminals, or run on many hosts and compare the output).
- Snippets (with parameters, and an optional snippet bar) and command history.
- Paste protection, sudo password filling, session logs, keyword highlighting, new-output markers on background tabs and notifications when long commands finish.
- 26 built-in terminal color schemes, set per host and per group, plus importing scheme files from Windows Terminal, iTerm2, Xshell, MobaXterm and others.
- Resource monitor and network latency; a host tools panel (processes, systemd services, Docker, network connections).
- Encoding switch (GBK, Big5), rz / sz and trzsz, pasting screenshots.
- Customizable shortcuts: Ctrl-based on Windows and Linux, with one-click Xshell and MobaXterm key presets; ⌘-based on macOS like Terminal.app and iTerm2 (the SFTP file list follows Finder), with every Control combination going to the terminal. Custom shortcuts are saved per platform, so each keeps its own after syncing. The kitty keyboard protocol.
- Local shells (PowerShell, Command Prompt, Git Bash and more, plus WSL distributions, on Windows; bash, zsh, fish and more on macOS and Linux).

### Files

- Two-pane SFTP with drag-and-drop between local and remote; a transfer queue, resuming transfers and reconnecting automatically.
- Changing permissions, following the terminal directory, editing remote files, opening SFTP as root, and remote file name encodings (GBK, Big5); the file lists can be used entirely from the keyboard.
- File management inside WSL.

### Keys and port forwarding

- Key library: import, generate (Ed25519, RSA), deploy public keys, export.
- Local, dynamic (SOCKS) and remote port forwarding, reconnecting automatically after a drop.

### Command-line tool and AI

- The `termlet` command: list hosts, run commands (also in a terminal already open in Termlet), upload and download single files.
- Off by default and allowed per host, with optional separate credentials for the command-line tool; the credentials never leave Termlet.
- When Termlet isn't open, `termlet` starts it in the background (can be turned off in Settings).
- Dangerous commands are blocked or need approval, and every call goes into an audit log.
- One-click installation of the Agent Skill (Claude Code, Codex and others).

### Data and security

- Encrypted credentials, with the master key in the system keychain (Windows Credential Manager, the macOS keychain, or the Secret Service on Linux; a master password when none is available); app lock (lock password, or Windows Hello on Windows).
- Importing hosts from `~/.ssh/config`, Xshell, FinalShell, MobaXterm, Tabby, Termora and WindTerm; exporting them as a Termlet host file or ssh_config.
- Encrypted full backups (restorable on another computer) and daily local snapshots.
- Sync between computers through a local folder or WebDAV, end-to-end encrypted and merged item by item.

### Privacy and diagnostics

- Anonymous usage statistics: on by default, sent at most once a day, with nothing that identifies this computer; turn them off any time or view the exact message to be sent under Settings → About → Privacy (see the [privacy notice](https://termlet.dev/en/privacy/)).
- Sending crash reports automatically: off by default; once on, only a scrubbed summary is sent, never memory dumps. A report the receiver rejects is not sent again and doesn't hold up later ones.
- Diagnostics (without host addresses, credentials or commands) and crash records kept on this computer.

### App

- Interface and setup wizard in 简体中文 (Simplified Chinese) / 繁體中文 (Traditional Chinese, Taiwan usage) / English; when following the system, Traditional Chinese is used on systems set to Taiwan, Hong Kong or Macao. Light / dark themes (or following the system).
- Wrapped Chinese descriptions and hints in the interface follow the usual line-breaking rules: punctuation such as full stops and commas never starts a line, opening brackets and quotation marks never end one, and dashes and ellipses aren't split across lines.
- Groups and sections in the host list start collapsed, and the ones you expand stay expanded after a restart; after you create or edit a host or group, the tree expands to it and selects it.
- System and brand logos (from Simple Icons): for identified remote systems, for Git Bash, bash, zsh, nushell and WSL distributions under This Computer, on the Docker tab of host tools, and in the command-line tool's approval dialog (when Claude Code or Gemini CLI makes the request). "Icons" (Color / Monochrome) under Settings → General applies to both file icons and these logos.
- On macOS, an app menu bar (Termlet, Shell, Edit, View, Window, Help) lists the common commands with their shortcuts; ⌘Q asks first about open connections, unfinished transfers and unsaved files.
- Windows setup wizard: installs for the current user only, with no administrator rights needed. The Linux tar.gz comes with `install.sh`, which adds Termlet to the application menu and links `termlet` into `~/.local/bin` without root.
- Automatic updates on Windows from Termlet's download site `dl.termlet.dev`, falling back to GitHub Releases (github.com/termlet/termlet), with signature verification. macOS and Linux check and verify the same way, then tell you about the new version and open the download page. Each release comes with a signed `SHA256SUMS` for checking by hand (see [Checking your download](README.en.md#checking-your-download)).
